## ▶️ Запуск на macOS

Для macOS в проекте настроен компилятор `/usr/bin/clang++` с C++17.

1. Открой **всю папку проекта** в Visual Studio Code.
2. Установи расширение **Code Runner** (`formulahendry.code-runner`). VS Code может предложить его автоматически.
3. Открой нужный `.cpp` и нажми **Run Code ▶** в правом верхнем углу редактора.
4. Программа запустится во вкладке **Terminal** снизу. Если код использует `std::cin` или `scanf`, введи данные там.

Встроенный терминал - это часть VS Code, а не отдельное окно macOS. Старую длинную команду `cd ... && g++ ...` больше вводить не требуется.

> **Не путай две кнопки запуска.** Кнопка Code Runner выполняет программу; кнопка от Microsoft C/C++ открывает выбор компилятора и отладчика. В настройках этого проекта вторую кнопку мы скрыли, чтобы запуск был понятнее.

Если кнопка Code Runner не появилась, проверь, что расширение установлено и включено, затем выполни **Developer: Reload Window** через палитру команд (`Cmd + Shift + P`). Запасной способ: **Terminal → Run Task… → C++: Build and run active file (terminal)**.

### Отладка

Для остановок на строках кода используется расширение **CodeLLDB** (`vadimcn.vscode-lldb`):

1. Открой **Run and Debug** слева.
2. Один раз выбери **C++: Debug (integrated terminal, CodeLLDB)**.
3. Нажми зелёную кнопку запуска в панели Run and Debug.

Это отдельный режим, он нужен для проверки переменных и пошагового выполнения, а не для обычного запуска.

## 🪟 Запуск на Windows 11

Для Windows в проекте добавлен отдельный профиль **C++: Debug (Windows 11, MinGW-w64)**. Конфигурации macOS сохранены без изменений.

### Установка компилятора и отладчика

1. Установи [MSYS2](https://www.msys2.org/) (обычный путь установки: `C:\msys64`).
2. Открой терминал **MSYS2 UCRT64** и установи набор инструментов командой:

   ```bash
   pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain
   ```

3. Добавь `C:\msys64\ucrt64\bin` в переменную среды Windows **Path** и полностью перезапусти VS Code.
4. В терминале VS Code проверь `g++ --version` и `gdb --version`. Обе команды должны работать.

Официальная инструкция: [VS Code - C++ с MinGW](https://code.visualstudio.com/docs/cpp/config-mingw).

### Сборка и запуск

1. Открой **всю папку репозитория** в VS Code и установи расширение **C/C++** от Microsoft (`ms-vscode.cpptools`).
2. Открой нужный файл `.cpp` (каждый файл содержит свой `main()`).
3. Для запуска с отладкой открой **Run and Debug**, выбери **C++: Debug (Windows 11, MinGW-w64)** и нажми **F5**. Программа с вводом `cin` или `scanf` работает во встроенном терминале.
4. Для обычного запуска без отладки выбери **Terminal → Run Task… → C++: Build and run active file (Windows terminal)**.

Windows использует `g++.exe` и `gdb.exe` из **Path**. Если появляется ошибка «g++/gdb not found», проверь установку MSYS2, путь `C:\msys64\ucrt64\bin` и перезапуск VS Code.

Как и на macOS, каждый файл собирается отдельно в `.build/` рядом с исходником. На Windows исполняемый файл получает расширение `.exe`; содержимое `.build/` игнорируется Git.

> **Важно:** кнопка расширения Code Runner **Run Code ▶** в текущих настройках проекта настроена под macOS и `/usr/bin/clang++`. На Windows для предсказуемого запуска используй профиль **F5** или задачу из меню **Run Task**.

## 🛠️ Что происходит при запуске

```text
Выбранный .cpp → clang++ → .build/имя_файла → запуск в Terminal
```

Компилятор собирает активный файл. Новый исполняемый файл попадает в скрытую от Git папку `.build/` рядом с исходником. В репозитории остаются исходные тексты и настройки, а не скомпилированные программы.

## 📝 Заметки о решениях

Это **учебные** программы, некоторые из них ещё требуют проверки или исправлений. Например:

- В `lab1/lab1_3.cpp` есть обращение к имени `number`, которого нет среди объявленных переменных.
- В заданиях с двумерными массивами размер иногда задаётся переменной. Clang на macOS может принимать это как расширение, но такой массив не является стандартным C++17.

Я намеренно не исправлял эти места автоматически: важно сначала самостоятельно разобраться в причине ошибки.

В [`notes/runMain.txt`](notes/runMain.txt) сохранена прежняя команда запуска **как историческая заметка**. Она ссылается на старое расположение файла и не нужна для нового способа запуска.
