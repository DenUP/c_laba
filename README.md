# Лабораторные работы по C/C++

Учебный репозиторий с моими решениями лабораторных работ и упражнениями по C/C++.

Здесь я постепенно изучаю основы языка, циклы, массивы, векторы, строки и работу с памятью. Исходные файлы `.cpp` сохраняются отдельно, чтобы можно было возвращаться к прежним решениям и видеть прогресс.

## Как запустить программу с вводом данных на macOS

Используется **Visual Studio Code** и компилятор **clang++** из Apple Command Line Tools. Открывайте в VS Code **всю папку проекта**, а затем нужный файл `.cpp`.

### Способ 1. Обычный запуск (без отладки)

1. Откройте, например, `lab5_1.cpp`.
2. В меню выберите **Terminal → Run Task…**.
3. Выберите **C++: Build and run active file (terminal)**.
4. Программа скомпилируется и откроется во встроенном терминале. Если она использует `std::cin` или `scanf`, вводите значения там.

Длинные команды вида `cd ... && g++ ... && ./...` вводить вручную не нужно.

### Способ 2. Кнопка Run Code

Если установлено расширение **Code Runner** (`formulahendry.code-runner`), откройте нужный `.cpp` и нажмите **Run Code**.

В настройках проекта уже включён запуск в терминале, поэтому ввод с клавиатуры будет работать. Запускается **весь файл**, даже если в редакторе выделен фрагмент кода.

### Способ 3. Отладка с точками останова

- **C++: Debug (integrated terminal, CodeLLDB)** - ввод во встроенном терминале VS Code. Для этого режима нужно установить расширение **CodeLLDB** (`vadimcn.vscode-lldb`).
- **C++: Debug (macOS Terminal)** - вариант со стандартным расширением Microsoft C/C++. Ввод происходит в отдельном окне «Терминал» macOS; при первом запуске macOS может запросить разрешение.

Нужную конфигурацию выбирают в разделе **Run and Debug**, затем нажимают **F5** (на некоторых Mac - **fn+F5**). Вкладка **Debug Console** предназначена для отладчика и не является обычным терминалом ввода.

## Как устроен проект

- `lab4_*.cpp`, `lab5_*.cpp`, `lab6_*.cpp` - исходники учебных заданий.
- `main.cpp` и другие `.cpp` - упражнения и эксперименты.
- `help.txt` - личные заметки по синтаксису.
- `.vscode/` - настройки сборки, запуска и отладки.

При запуске новые исполняемые файлы складываются в папку `.build/` рядом с исходником. Она не добавляется в Git. Некоторые **старые** исполняемые файлы и каталоги `.dSYM` уже присутствуют в истории репозитория: эти настройки не удаляют их автоматически.

## Важно

При каждом запуске сначала откройте тот `.cpp`, который хотите проверить: настройки компилируют **активный файл**. Например, `lab5_1.cpp` будет собран в `.build/lab5_1`.

Задача репозитория - не только хранить работающий код, но и разбираться, *почему* каждое решение работает.
